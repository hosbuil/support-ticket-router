# Support Ticket Router

An educational multinomial Naive Bayes text classifier implemented using Python's standard library. Routes synthetic tickets to account, network or storage support, or abstains when there is insufficient evidence.

## Origin

Initial code, synthetic dataset, tests and documentation generated by OpenAI Codex on 23 October 2026 at the repository owner's request. Personal implementation contributions have not yet been made. This repository is a starting point for learning and future contributions, not evidence of independently authored ML work.

## Run (Python 3.10+)

```sh
python3 router.py
python3 router.py --text "wifi router disconnected"
python3 router.py --text "unfamiliar gibberish"
python3 -m unittest -v
```

No downloads, dependencies, API keys or network calls. Use synthetic text; the CLI prints its input's known tokens, so avoid personal or private ticket content.

## Model and evaluation

- Lowercase alphabetic tokens and bag-of-words counts; Laplace smoothing with alpha=1.
- Vocabulary, class priors and token counts are learned exclusively from training rows.
- Log-space scoring avoids direct multiplication of tiny probabilities.
- Default acceptance threshold is 0.7, chosen before evaluation. Scores are normalized model outputs, not calibrated probabilities or guarantees.
- Empty input or input without training-vocabulary tokens always abstains.
- Evaluation reports a confusion matrix, coverage, accuracy with abstentions counted as errors, accepted-only accuracy, and a majority-class baseline. Accepted-only accuracy is null when no tickets are accepted.
- Duplicate text across train/test splits is rejected.

`tickets.csv` contains 18 handcrafted training examples and 9 held-out examples, balanced across 3 labels. All examples are AI-generated and synthetic. The holdout shares simple vocabulary with training examples. It is only a plumbing demonstration, not independent evidence of generalization or production accuracy. There are no real support users, deployments or measured business outcomes.

## Limits

English-only toy tokenizer. No semantic understanding, spelling correction, multilabel routing, model persistence or secure hosted service. Repeated known words may produce overconfident scores. A few matching words do not establish that a ticket belongs to a known category. Scores and abstention require evaluation on realistic independently labeled data before practical use.
